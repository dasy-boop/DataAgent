# DataAgent 面试现场演示（约 5 分钟）

这份脚本用于介绍**当前已实现的系统**。先在本机完整走一遍，再在面试现场演示；模型回答有随机性，讲解时以当次屏幕上的计划和数据为准。

## 演示前检查

1. 在 PowerShell 中运行 `cd D:\DataAgent`，启动 `./run_dev.cmd`（PowerShell 也可使用 `.\run_dev.cmd`）。看到 `Uvicorn running on http://127.0.0.1:8001` 后保留终端窗口。
2. 打开 `http://127.0.0.1:8001/agent.html`，确认侧边栏数据集显示约 112,816 条记录。用“查看数据概览”展示字段和样例。
3. 确认 `.env` 中的模型接口可用。不要在屏幕共享时展示 `.env` 或 API 密钥。
4. 事先运行 `& .\.venv\Scripts\python.exe -m pytest tests -q`；评测报告页面可以加载已经生成的本地 JSON 报告，无需现场再调用 7 次模型。

## 现场操作与讲解

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:40 | 打开分析页与数据概览 | “当前版本在 112,816 条招聘记录上分析，数据以 Parquet 保存。先查看字段和数据质量。” |
| 0:40–2:00 | 新对话输入“英国的 Data Analyst 岗位最常见的技能有哪些？” | 展开“查看分析计划”：模型应先筛选国家和岗位，再调用 `count_skills`。这是未写入固定评测集的问题，展示自然语言到工具计划的转换。 |
| 2:00–2:40 | 展开“查看图表与结果明细” | 技能次数来自 Pandas，比例以技能可解析岗位为分母。一次预演得到 13 条匹配岗位，Python 和 SQL 各出现 7 条；实际结果以当次运行和数据集为准。 |
| 2:40–3:30 | 新对话输入“比较 Data Analyst 和 Software Engineer 岗位最常见的技能” | 展示两个独立岗位组的技能图表和各自的分母；说明不能连续筛选两个岗位名称，否则会误算为交集。 |
| 3:30–4:10 | 输入“预测明年数据分析师岗位的平均薪资” | 说明只有历史数据筛选和统计工具，预测应给出“不支持”，不能把历史平均值冒充预测。 |
| 4:10–5:00 | 打开 `/eval.html`，加载最新的 `eval/reports/benchmark_*.json` | 展示计划匹配、执行结果与失败原因。固定评测集用独立标准答案做回归验证，不是问题白名单，也不能代表所有问题的准确率。 |

需要展示 API 时，打开 `http://127.0.0.1:8001/docs`，重点介绍 `/agent/plan`、`/agent/execute` 和 `/agent/ask/stream` 的关系。

## 能讲清的技术决策

- **为什么分离规划与执行？** 模型给出 JSON 工具计划；执行器只接受注册的工具、字段和参数。真实统计由 Pandas 完成，可以单独测试和核对。
- **怎样防止编造数字？** 图表直接读取工具返回值，回答基于同一次查询的结果与少量岗位样本。无法支持的预测和缺失字段进入拒答或澄清分支。
- **怎样验证 Agent？** 测试分三层：`pytest` 检查工具与接口；固定题集检查模型选的工具和结果；拒答与连续追问有单独评测。最近一次本地正常分析评测为 7/7，`pytest` 为 184 项通过。这是当前小样本回归结果。
- **目前的局限？** 仅使用固定招聘数据与受限 Pandas 工具；没有通用数据上传、MySQL/SQL 工具或完整图表类型自动选择。模型服务不可用时，已有评测报告仍可展示，但不能声称现场完成了实时分析。

## 如果现场遇到问题

- **网页打不开：** 检查启动终端是否仍显示服务运行，确认地址和端口是 `127.0.0.1:8001`，且没有多开启动器。
- **模型接口失败：** 检查本地网络和 `.env` 配置；不要展示密钥。可以先展示已有报告，再说明实时提问依赖外部模型服务。
- **答案与预演数字不同：** 先看“查看分析计划”和当前数据范围，再看工具结果；不要背诵或强行解释预演数字。如果计划错误，记录为待改进案例。
- **评测失败：** 打开 JSON 报告区分“计划未匹配”和“计算结果不符”；不要只报总通过率。

演示结束时可以用一句话概括项目：“我把模型的自然语言规划、受限工具执行、真实数据可视化和可复现评测连成了一条可检查的链路。”
