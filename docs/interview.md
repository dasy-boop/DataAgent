# DataAgent 简历与面试讲解素材

这份材料只描述当前已实现、可现场展示的版本。面试时请按自己的实际参与情况调整“我负责”的表述，并先亲自走通 [演示流程](demo.md)。

## 简历写法

**项目名：** DataAgent｜招聘数据分析 Agent 与自动评测平台

**技术栈：** Python、FastAPI、Pandas、Pydantic、JavaScript、pytest、LLM API

可以放进简历的两条描述：

1. 构建自然语言数据分析流程：将用户问题转为受限工具计划，经字段和参数校验后在 112,816 条招聘记录上执行 Pandas 筛选与统计，返回可追溯的数据依据、中文解释和图表；支持当前对话内的连续追问。
2. 设计回归评测：固定题集分别核对模型工具计划和真实计算结果，另测拒答、澄清和连续追问；当前本地记录为 7/7 道正常分析题通过、184 项 pytest 测试通过。**7/7 是小规模题集结果，不是总体准确率。**

如果简历空间只够一行，可写：

> 基于 FastAPI、Pandas 和 LLM API 实现可解释的数据分析 Agent，将自然语言问题转换为受校验的工具计划，并用独立标准答案评测计划与计算结果；支持技能对比、图表展示和连续追问。

不要写“支持任意数据集上传”“自动生成 SQL”“已接入 MySQL”“所有问题 100% 准确”，因为当前版本没有这些能力或证据。

## 90 秒项目介绍

> 我做的是一个面向招聘数据的分析 Agent。用户可以用自然语言问岗位数量、国家分布或岗位技能。模型先生成工具调用计划，后端只允许调用注册过的 Pandas 工具，并检查字段和参数；岗位数和技能次数由程序在固定数据集上计算，模型再依据结果生成中文解释。前端把分析计划、依据、明细和图表放在同一对话里。
>
> 我特别做了自动评测。固定题集既看模型有没有选对工具，也看最终数字对不对；拒答和连续追问另有测试。这样模型说得流畅但算错时仍会失败。当前正常分析回归题是 7/7，通过的 pytest 测试有 184 项，不过题集很小，不能把它宣传成真实场景的总体准确率。
>
> 当前版本固定读取招聘数据，只开放受限 Pandas 工具。下一步才是通用数据上传、更多统计工具和更广的评测覆盖。

## 常见追问

**1. 为什么这算 Agent，而不是给模型套个聊天界面？**

模型不直接返回预设答案，而是根据问题和可用工具生成计划。执行器逐步调用真实数据工具，后续回答引用工具结果。可以在页面展开“查看分析计划”，也能通过 `/agent/plan` 与 `/agent/execute` 分别检查规划和执行。

**2. 如何限制模型乱调用工具或使用不存在的字段？**

工具注册表定义可调用操作，执行器检查工具名、允许的参数、字段是否存在以及工具自己的参数范围。模型输出还要经过 Pydantic 结构校验。系统能防住不合法调用，但不能保证每个合法计划都符合用户意图，所以还要评测和人工检查。

**3. 技能频次的分母是什么？**

先筛选目标岗位，再解析 `skills_required`。同一条岗位里重复出现的同一技能只计一次；比例的分母是该组技能字段可解析的岗位记录数，不是全数据集行数。比较两类岗位时，两个组分别筛选、分别计算分母，不能把两个关键词连续筛选成交集。

**4. 怎样验证数字不是模型编造的？**

工具返回计数、排名和分母，图表直接使用这些结果。评测题的标准答案由原始 Parquet 独立遍历计算，再分别检查计划和最终结果。文字解释仍可能不充分或误读，不能只凭数值测试就保证回答质量。

**5. 7/7 代表什么？**

仅代表 2026-10-07 本地七道固定正常分析回归题都通过。当时的题目覆盖筛选、统计、技能频次、两类岗位对比和空结果；另有三道拒答与澄清题及三轮连续追问。模型、接口或数据变动后都应重跑，不能外推到所有自然语言问题。

**6. 遇到没有数据或工具不支持的问题怎么办？**

计划有 `cannot_answer` 和 `needs_clarification` 分支。例如没有预测工具时，不能拿历史均值冒充“明年薪资”；主题含糊时询问缺少的对象或指标。能回答但某字段缺失时，应继续使用有证据的字段，并说明限制。

**7. 为什么目前用 Pandas，没有 MySQL 或 SQL？**

第一版优先把“自然语言规划 → 受限工具执行 → 可核对评测”打通。固定 Parquet 数据配合 Pandas 更容易控制统计口径和复现结果。若扩展到多数据集和复杂查询，需要增加数据接入、Schema 管理、SQL 沙箱与权限控制，并为新工具补测试。

**8. 你会怎样改进这个项目？**

优先增加可上传数据集及字段映射，扩充到更有代表性的评测题，并保存每次评测的模型版本、耗时与失败类别。图表类型和文字质量也需要更系统的验证。上传与 SQL 都是计划，不应在当前简历中写成已完成。

面试前请打开本地页面亲自解释一次工具计划、真实数据结果和评测报告；如果某个数字与这里的预演值不同，应以当次运行结果为准。
