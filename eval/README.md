# 自动评测

`benchmark.json` 第二版包含六道中文题，覆盖国家统计、公司统计、岗位筛选、先筛选后统计、技能频次比较、无匹配记录。

保持后端运行，在项目根目录执行：

```powershell
# 固定计划校验：不调用模型，只验证真实数据上的执行结果
& .\.venv\Scripts\python.exe .\eval\run_benchmark.py --execution-only

# 完整评测：每题通过 /agent/ask 调用一次模型，产生 API 用量
& .\.venv\Scripts\python.exe .\eval\run_benchmark.py
```

报告保存至 `eval/reports/`，保留以往报告；任一题未通过时退出码为 1。

## 判定方式

- 计划匹配：检查全部工具调用的顺序和参数；允许筛选关键词大小写差异，以及省略值为 10 的默认 `top_n`。
- 统计结果：检查类别、数量、降序和前几名完整性。截断处数量相同的类别允许互换。
- 筛选结果：检查记录数、岗位名称及清洗国家两列的无序多重集摘要；不会把重复记录去掉。此项不验证其他列内容。
- 无匹配结果：必须请求成功且返回空列表，网络错误不算通过。
- 技能比较：检查匹配岗位数、技能可解析岗位数，以及 SQL 和 Python 分别涉及的岗位记录数；允许模型选择 2 至 50 的 `top_n`，但必须先筛选岗位、再调用 `count_skills`。
- 固定计划模式的 `plan_accuracy` 为 `null`，不能用它声称模型准确率。

标准答案由原始 Parquet 的独立遍历与计数计算，不使用 `run_plan` 或被测工具。技能题独立解析原始 JSON 列表，每条岗位的同一技能最多计数一次。固定别名规则包括美国和英国的已知别名，未声称覆盖全部国家别名。数据文件 SHA-256 固定在基准中；数据发生变化时停止评测，须先人工复核并更新基准。报告同时记录基准文件摘要。

这六道题是小规模回归基准，不能代表模型在所有自然语言问题上的整体准确率。正确计划但错误结果仍判为未通过；可接受但不符合固定步骤的其他计划会单独反映为计划未匹配。

## 连续对话评测

保持后端运行，在项目根目录执行：

```powershell
& .\.venv\Scripts\python.exe .\eval\run_chat_benchmark.py
```

脚本通过网页使用的 `/agent/ask/stream` 接口依次提问“西部数据有哪些岗位”、“这些岗位主要需要什么技能”、“其中哪些岗位可能适合应届生”，并将前面完成的问答传给下一轮。每轮会调用已配置的模型生成计划和文字分析，因此会产生 API 用量。评测检查回答确由模型流式生成、查询仍限定在 Western Digital 的 8 条记录内，以及最后一轮没有把经验要求缺失误判为适合应届生。

报告保存至 `eval/reports/chat_*.json`；任一轮未通过时退出码为 1。该检查是针对当前数据集的回归测试。若数据集更换、Western Digital 记录数发生变化，需先人工复核并更新 8 条这一预期。文字检查只覆盖关键风险，不能代替人工审阅分析是否充分、正确。
